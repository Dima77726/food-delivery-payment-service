# food-delivery-payment-service

Сервис платформы доставки еды. Платформа целиком (docker-compose, наблюдаемость, Postman,
общая документация) — в репозитории [food-delivery-platform](https://github.com/Dima77726/food-delivery-platform);
контракты событий, gRPC и REST — в [food-delivery-contracts](https://github.com/Dima77726/food-delivery-contracts).

## Сборка

Контракты лежат в GitHub Packages, а он требует токен даже для чтения. Один раз в
`~/.m2/settings.xml`:

```xml
<servers>
  <server>
    <id>github</id>
    <username>ВАШ_GITHUB_ЛОГИН</username>
    <password>ТОКЕН_С_ПРАВОМ_read:packages</password>
  </server>
</servers>
```

```bash
./mvnw verify
```

Интеграционным тестам нужен Docker (Testcontainers).

## Образ

```bash
docker build --secret id=maven_settings,src=$HOME/.m2/settings.xml -t food-delivery-payment-service .
```

CI публикует образ в `ghcr.io/<владелец>/food-delivery-payment-service` на каждый пуш в `main` и `dev`.

## Платёжный шлюз

Сервис исполняет команды саги оплаты («спиши», «верни») через `PaymentGateway`. Реализаций две,
выбирает настройка `app.payments.gateway` (`PAYMENT_GATEWAY`):

| Значение | Что делает |
|---|---|
| `simulated` (по умолчанию) | заглушка: подтверждает любое списание, сумма с копейками `.13` — отказ банка |
| `stripe` | настоящий Stripe REST API: `PaymentIntent` со списанием и `Refund` для возврата |

### Stripe (тестовый режим)

1. Заведите аккаунт Stripe и скопируйте **тестовый** секретный ключ (`sk_test_…`) из Dashboard →
   Developers → API keys. Тестовый режим бесплатен и денег не двигает.
2. В `.env` платформы:
   ```
   PAYMENT_GATEWAY=stripe
   STRIPE_API_KEY=sk_test_...
   ```
3. Пересоздайте сервис: `docker compose --profile full up -d payment-service`. Без ключа при
   `stripe` сервис не стартует — осознанно, а не падает на первой оплате.

Что важно знать:

- **Карту клиента сервис не видит.** В команде оплаты её нет, и платёж подтверждается тестовым
  способом оплаты Stripe (`pm_card_visa`). Для боевой оплаты клиент должен получить способ оплаты
  у Stripe (Elements) и передать его в команде — это изменение контракта событий, а не шлюза.
- **Ключ идемпотентности уходит Stripe в каждом запросе** (`charge-…`, `refund-…`). Вызов шлюза
  стоит внутри транзакции: если процесс упадёт между ответом Stripe и коммитом, команда придёт
  снова, и Stripe вернёт прежний результат, а не спишет второй раз.
- **Отказ банка — результат, остальное — исключение.** Ответ 402 записывается как `FAILED` с
  причиной. Сеть, таймаут, 5xx, 429 и неверный ключ откатывают транзакцию: команда уходит на
  повтор и затем в DLT. Клиент не получает отказ из-за чужого сбоя.
- **Возврат идёт по платежу у провайдера** (`payment.provider_reference`). У платежей без
  ссылки (наличные, заглушка, проведённые до миграции `002`) возвращать у провайдера нечего.
- **Валюта** по умолчанию `usd` (Stripe не принимает рубли на новых аккаунтах); сумма заказа
  уходит как есть, без пересчёта курса. Меняется `STRIPE_CURRENCY`. Сумма обязана иметь не более
  двух знаков после запятой.
- **Отказ по сумме `.13` в тестовом режиме** сохранён: такая сумма подтверждается тестовой картой,
  которую Stripe отклоняет (`pm_card_chargeDeclined`). Так сценарии Postman работают и со Stripe. С
  боевым ключом (`sk_live_…`) этого нет.
- Соединение с базой занято на время HTTP-вызова (не дольше `read-timeout`, 10 с). Если это станет
  заметно, шаг разбивается на «записать PENDING и закоммитить → списать → записать исход» —
  тогда понадобится и уборщик платежей, застрявших в PENDING.

## Пересчёт по курсу ЦБ РФ (SOAP-клиент)

Stripe не принимает рубли на новых аккаунтах, а заказы у нас рублёвые. С `FX_ENABLED=true` сумма
заказа перед списанием пересчитывается в валюту провайдера (`STRIPE_CURRENCY`, по умолчанию `usd`)
по официальному курсу ЦБ РФ. Курс запрашивается по SOAP: `DailyInfo.GetCursOnDateXML`
(`FX_CBR_URL`, по умолчанию `https://www.cbr.ru/DailyInfoWebServ/DailyInfo.asmx`).

- Курс кэшируется на 6 часов: ЦБ публикует его раз в сутки, ходить за ним на каждый платёж незачем.
  Одновременные первые платежи делают один запрос.
- Если ЦБ недоступен, используется устаревший курс не старше 72 часов (с предупреждением в журнале);
  дальше — исключение, платёж не отклоняется, а команда оплаты повторяется. Таймауты: соединение 3 с, ответ 5 с.
- Сумма округляется вверх до цента. Исходная сумма в рублях, курс и его дата уходят в метаданные платежа Stripe.
- Возврат делается без суммы, то есть полный: пересчитывать его по сегодняшнему курсу нельзя, он разошёлся бы со списанием.
- Выключено по умолчанию; без флага сервису не нужен выход к ЦБ.
